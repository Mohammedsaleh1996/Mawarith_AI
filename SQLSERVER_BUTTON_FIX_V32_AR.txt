# إصلاح v32 - فحص SQL Server من نفس بيانات النموذج

المشكلة التي ظهرت:
- الشبكة شغالة و Test-NetConnection نجح.
- لكن زر فحص الاتصال داخل الداشبورد لم يكن يعطي نتيجة واضحة.

سبب المشكلة:
- زر فحص الاتصال كان يعتمد على الإعدادات المحفوظة سابقًا فقط.
- لو المستخدم كتب بيانات SQL Server في النموذج ولم يضغط حفظ أو كانت كلمة المرور غير محفوظة بعد، كان الاختبار يستخدم Config قديمًا أو ناقصًا.

الإصلاح:
- أزرار SQL Server الآن ترسل بيانات النموذج الحالية مباشرة إلى السيرفر.
- لا تحتاج تضغط حفظ قبل فحص الاتصال.
- كلمة المرور المكتوبة في النموذج تُستخدم في الاختبار مباشرة.
- لو تركت كلمة المرور فارغة، يستخدم النظام كلمة المرور المحفوظة في Registry إن وجدت.
- أي خطأ من pyodbc/ODBC/SQL Server يظهر داخل صندوق النتيجة، ويسجل في صفحة الأحداث/الأخطاء.

طريقة الاختبار:
1. افتح الإعدادات.
2. املأ بيانات SQL Server.
3. اضغط فحص الاتصال.
4. اقرأ النتيجة في صندوق SQL Server.
5. إذا نجح، اضغط إنشاء القاعدة والجداول، ثم مزامنة الآن.

ملاحظات:
- نجاح Test-NetConnection يعني أن البورت مفتوح فقط، وليس أن تسجيل الدخول أو ODBC يعمل.
- إذا ظهر pyodbc_not_installed فشغل install_dashboard_requirements.bat.
- إذا ظهر driver not found فثبت ODBC Driver 18 أو 17 for SQL Server.
