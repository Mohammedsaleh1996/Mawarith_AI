تحديث v34 - SQL Server Sync + Telegram Token Guard

ما تم تنفيذه:
1. عرض حالة SQL Server داخل لوحة حالة النظام:
   - غير مفعل
   - متصل
   - منقطع / يعمل محليًا على SQLite
   - حالة المزامنة حسب فروق عدد الصفوف بين SQLite و SQL Server.

2. مزامنة تلقائية ثنائية الاتجاه:
   - SQLite → SQL Server
   - SQL Server → SQLite
   - بدون حذف بيانات من أي طرف.
   - عند انقطاع SQL Server يستمر المشروع على SQLite ولا يتوقف.
   - عند عودة SQL Server تتم إعادة المزامنة تلقائيًا.
   - تمت إضافة مزامنة فورية خفيفة بعد تسجيل المحادثات/الأحداث/الإشعارات، مع worker دوري حسب Sync interval.

3. إصلاح حماية Telegram Token:
   - أي حفظ إعدادات لا يملك توكن Telegram حقيقي لا يستطيع مسح التوكن المحفوظ.
   - القيم الفارغة أو المقنعة مثل VDGM...8763 لا تُكتب كتوكين.
   - نفس الحماية مطبقة على WaPilot API Token و SQL Server Password.

4. SQL Server ليس نقطة فشل:
   - لو SQL Server فصل، البوت والداشببورد يستمران على SQLite.
   - تسجل الأخطاء في الأحداث.
   - تتم إعادة المحاولة تلقائيًا لاحقًا.

طريقة الاستخدام:
- شغل run_dashboard_full_auto.bat
- ادخل الإعدادات وتأكد أن SQL Server مفعّل والمزامنة مفعلة.
- اضغط فحص الاتصال ثم إنشاء القاعدة والجداول ثم مزامنة الآن.
- حالة SQL Server ستظهر في كرت حالة التشغيل.
